2 · Row lifecycle — what the editor shows over time

StateTournament cellBehavior on PLE approval
Paired (today's model) All Time Rumble Books that existing tournament's bracket exactly as today — unchanged.
Spec (new) Crown's Cup · spec First approval creates one SCHEDULED tournament from the spec and stores it back on the row (the Tournament cell switches from the spec badge to the tournament name). Entrant count, final rule and rules pool come from the spec.
Consumed — (cleared) After the payoff the row degrades to a plain type/rule row: tournament and all spec fields cleared, so it can never mint a second instance. Spec-only rows are removed entirely.

Editing the spec is only possible while the instance is SCHEDULED (the instance follows the standard tournament edit rules). Once IN_PROGRESS or COMPLETE the spec fields display read-only.

4 · Where seeded tournaments appear

The catalog also seeds real Tournament rows at startup (universe-less, SCHEDULED, no entries — like segment type seeds), so the two places that list tournaments see them without any template involvement:

All Time Rumble
Deadly Combat · seeded
Crown's Cup — SCHEDULED
Deadly Combat — SCHEDULED (seeded)

Pairing the seeded Deadly Combat row with a weekly template is the zero-config route: no spec needed, the campaign's deadlyCombatWins counter only advances for tournaments carrying the deadly_combat code.
